## 3. The IVT layer is derived from the AR paint, not from IVT (report B's real bug)

`ewb_live/viz/exceedance.py`: `class_plane = ivt_class_plane(ivt_day[i], ar_paint)`
with `ar_paint = ar[i] & ~bridged[i]`, and `ivt_class_plane` writes 0 outside its
mask argument. `dashboard/mergedmap.js` then colours the AR layer *only* from
that plane and reads it for hover (`ivtAt`). Verified on the published frames:
the `.ivt` non-zero mask is **cell-identical** to the `.bin` AR plane for every
frame checked (single exception `2026081512`, 577 cells — the gap-bridge
footprint, which is intentional).

Consequence: there is no IVT field on the map — there is an AR-mask field with
IVT bins looked up inside it. Any screen, any marginal-threshold flicker of the
|∇²IVT| ≥ 2.5 test, and any seam/crop loss deletes the "IVT values" too, even
though IVT ≥ 400 is unchanged. The link-cap/centroid-screen fix does not touch
this: after it, IVT still vanishes wherever the AR mask does not paint.

Fix: compute the class plane from the IVT field itself (`ivt >= 250`, the first
bin edge) and keep the AR bit only as a paint/legend gate; publish the mask
state as a separate flag (the `bridged` plane already shows how).

## 6. Fixed and deployed (2026-11-10 21:51Z, this session)

The peer session in this worktree owned the linker/tropical/seam fixes; I added
what my measurements showed it had missed, and we both sign the same tree now.

| bug | fix | where |
|---|---|---|
| IVT values vanish with the AR paint (§3) | `.ivt` computed from the **IVT field** — class in the low 3 bits, bit 7 = IVT ≥ 400; `index.ivt = {schema: 2, bins, ar_min, above_bit}`; `LAYER_REV` v9 | `viz/exceedance.py::ivt_class_plane` |
| AR colour/hover follow a plane that is not the field | JS paints ramp **only where the `.bin` AR bit is set**, a faint tint for IVT ≥ 400 outside the mask, `ivtAt` masks the class, legend census gates on the paint bit, tooltip labels "not classified as an AR" | `dashboard/mergedmap.js` (built on the **live** dogfish js + the peer's ghost-plane hunks, so no lane's work was reverted) |
| one cyclone deletes weeks of AR (§5, reports B and C) | TC screen keeps its space-time **test** and narrows only its **consequence**: the flagged (track, step) pairs lose those steps; a track hit at every step is still dropped with reason `tc` | `events/ar_filter.py::_storm_pass`, `ar_filter_tracks` |
| a report can't be attributed from published data (§2) | `dropped[]` entries carry `bbox`; partially screened tracks publish `tc_steps` (+ `tc_name`, distance) and the ledger gains a `tc_masked` map | `events/ar_filter.py::_track_bounds`, `viz/exceedance.py` |
| disappearing/re-seeding ARs, prime-meridian slicing, crop clipping, ghost pixels | peer session's link caps (900 km / 40 steps), centroid tropical rule, seam-periodic mask (`events/ar_mask.py`), wide AR compute window, `bridged` plane 3 reaching the screen | already in this tree; deployed with the rest |
